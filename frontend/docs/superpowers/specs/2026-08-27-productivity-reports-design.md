# 日报 / 周报 / 月报设计

## 目标

新增只读的“数据报告”页面，把任务、番茄钟、每日计划、代币和笔记聚合为日报、周报、月报。报告应有丰富但轻量的可视化，并保持现有像素冒险风格、移动端可用和快速首屏。

## 数据范围

- 日报：上海时区逻辑日，04:00 至次日 04:00。
- 周报：逻辑日所在周的周一至下周一。
- 月报：逻辑日所在自然月首日至下月首日。
- 番茄钟和代币按时间戳查询；每日计划和笔记按日期查询；已完成任务按 `updated_at` 近似归入期间，界面明确标注口径。
- 所有查询均限定当前用户和当前报告范围，不新增数据库表或第三方图表库。

## 页面结构

1. 顶部：报告类型切换、上一期 / 本期 / 下一期导航、当前范围标题。
2. 核心指标：番茄钟数、专注分钟、完成任务、计划完成率、休息分钟、净获得代币。
3. 生产力指数：0–100 环形仪表与自动文字洞察。
4. 专注趋势：日报按小时、周报和月报按天显示 SVG 面积折线。
5. 工作节奏：24 小时柱状分布，展示高效时段。
6. 结构环图：工作/休息时长、每日计划状态。
7. 排行：任务专注排行、代币来源排行。
8. 活动日历：周期内每日专注强度和当日番茄钟数。
9. 回顾摘录：显示周期内最新笔记，作为定量数据的上下文。

## 架构

- `reportAnalytics.ts`：纯函数负责时间范围、分桶、聚合、评分和洞察，可独立单元测试。
- `api.ts`：新增一个范围化并行查询入口，只返回报告所需字段。
- `ReportCharts.tsx`：无第三方依赖的 SVG/CSS 图表组件。
- `Reports.tsx`：负责状态、加载、错误、周期导航和页面编排。
- `App.tsx` / `Layout.tsx`：懒加载路由和侧栏入口。

## 性能与错误处理

- 每次周期切换只发起一组并行范围查询；结果使用现有请求缓存按范围缓存 30 秒。
- 页面懒加载，不进入报告页时不下载图表代码。
- 空数据仍显示完整骨架和零值，不把“没有活动”当作错误。
- 查询失败显示可重试错误卡片，不影响其他页面。

## 验收标准

- 日 / 周 / 月范围正确，支持前后导航和返回本期。
- 所有指标由同一份范围数据计算，图表与数字口径一致。
- 移动端无横向溢出；无数据、单点数据、跨月周均可展示。
- 单元测试、TypeScript 构建和本地页面检查通过。
